## Daisy Azyl – website & build documentation

This repository contains the public website for **Daisy Azyl z.s.**, a small family-run animal shelter near Městec Králové.

### Website overview

- **Purpose**: Present the shelter, show animals available for adoption, and provide clear ways to support the organization.
- **Audience**: Primarily Czech-speaking visitors interested in adopting or supporting cats and dogs.
- **Technology stack**:
  - **Static site generator**: Eleventy (11ty).
  - **Templates**: Webflow-exported HTML with light Nunjucks/Liquid tags for includes, loops, and pagination.
  - **CMS**: Decap CMS (Git-based) editing `cms/animals.json`.
  - **Assets**: Webflow CSS/JS in `css/` and `js/`, plus optimized images generated via `@11ty/eleventy-img`.
- **Output**: Production builds are written to `_site/` and can be deployed to any static host.

### Pages & routes

- **Home** (`/`, `index.html`):
  - Hero section with intro copy, image grid, and CTA to the support section.
  - “Co děláme” section describing the shelter’s mission.
  - Adoption teaser showing up to 3 animals from `animals.animalsEnriched` with a “see more” button to `/adopce/` when there are more animals.
- **Adoption listing** (`/adopce/`, `adopce.html`):
  - Full list of adoptable animals rendered from `animals.animalsEnriched`.
  - If `animals.animals` is empty, shows: “Momentálně nemáme žádné pejsky a kočičky k adopci.”
- **Adoption detail** (`/adopce/<slug>/`, `adopce-detail.html`):
  - One page per animal generated by Eleventy pagination.
  - Shows tags, name, short description, hero image, tabbed detail cards (“Základní údaje”, “Povahové rysy”, “Zdravotní karta”), and an adoption CTA.
- **Admin (Decap CMS)** (`/admin/`, `admin/index.html`):
  - Loads Decap CMS and mounts into the `#nc-root` element.
- **Utility & error pages**:
  - `401.html` → `/401/`: password-protected utility page, explicitly marked `noindex`.
  - `404.html` → `/404/`: not-found page with link back to the home page, also `noindex`.
- **Generated files**:
  - `/sitemap.xml` – sitemap including `/`, `/adopce/`, and all animal detail pages.
  - `/robots.txt` – robots configuration pointing to the sitemap.
  - `/llms.txt` – AI discovery file (per llmstxt.org) describing the organization and how automated systems may use the site.

### Build pipeline

- **Install dependencies**:

```bash
npm install
```

- **Build static site with Eleventy** (outputs to `_site/`):

```bash
npm run build
```

- **Local preview**:

```bash
npm run serve
```

Then open `http://localhost:8080`.

### Minimal templating structure

- Shared pieces:
  - `/_includes/partials/head.njk` – document `<head>` (title, description, og/twitter; uses `title`/`description`/`ogImage` from front matter, or `animal` on adopce-detail).
  - `/_includes/partials/global-styles.njk` – Webflow global style embeds.
  - `/_includes/partials/navbar.njk` – main navigation (uses `currentPage` from front‑matter).
  - `/_includes/partials/footer.njk` – footer (also uses `currentPage`).
- Pages are still regular `.html` files (`index.html`, `adopce.html`, `adopce-detail.html`, …) with very small Liquid tags for includes and loops.

### Animal data

- Adoption listings and detail pages are driven from:

```text
cms/animals.json      (edited by Decap CMS)
_data/animals.js      (reads cms/animals.json, adds URL slugs, exposes global "animals")
```

- `animals.animals` contains the raw records from `cms/animals.json`.
- `animals.animalsEnriched` adds a computed `slug`, responsive image data (`image`, `imageSrcset`, `imageSizes`), and safe fallbacks when the source image is missing.
- Typical fields used by the templates include:
  - Identification & naming: `id`, `name`, `species`, `evidenceNumber`.
  - Basic info: `ageText`, `ageCategory`, `gender`, `breed`, `color`.
  - Dates & origin: `birthDate`, `foundDate`, `origin`, `guardian`.
  - Story & presentation: `shortDescription` (card + SEO, plain text), `longDescription` (detail page, markdown/rich text), `tags` (array of strings), `category` (e.g. `hledaji-domov`, `nove-prijati`).
  - Suitability flags: `suitableOutdoor`, `suitableWithCats`, `suitableWithDogs`, `suitableWithChildren`, `suitableWithOlderChildren`.
  - Health data: `panleukopeniaTest`, `felvTest`, `fivTest`, `neutered`, `firstVaccination`, `secondVaccination`.
- Slugs are generated in `_data/animals.js` using a Czech-aware `slugifyCzech` helper so that `/adopce/<slug>/` URLs stay readable (e.g. `/adopce/kocka-betuska/`).

- **Listing** (`adopce.html`): Loops over `animals.animalsEnriched` to render cards and links to each animal’s detail at `/adopce/<slug>/` (e.g. `/adopce/kocka-betuska/`).
- **Detail** (`sverenec-detail.html`): Uses Eleventy pagination (one page per animal) and binds each animal’s fields (name, tags, longDescription, image, etc.). URLs are SEO-friendly: `/sverenec/<slug>/`.
- When `animals.animals` is empty, no detail pages are generated and the listing shows “Momentálně nemáme žádné pejsky a kočičky k adopci.”

### Content editor (Decap CMS)

- Editor UI: `/admin/`
- Backend: **GitHub** (`matyldajandova/daisyazylweb`), commits go straight to `main`
- Production login: **Login with GitHub** (collaborators with write access)
- Local login: **local backend** — no GitHub OAuth on localhost (standard Decap workflow)

#### Local editing (standard Decap workflow)

GitHub OAuth is production-only. Locally, Decap talks to a small proxy that edits your working tree directly:

1. Terminal 1: `npm run serve` (site at `http://localhost:8080`)
2. Terminal 2: `npm run cms:local` (starts `decap-server` on port 8081)
3. Open `http://localhost:8080/admin/` → click **Work with Local Repository**

Changes made in the CMS are written to the repo working tree (e.g. `cms/animals.json`); review and commit them with git as usual. This is enabled by `local_backend: true` in `admin/config.yml` and only takes effect when `decap-server` is running.

#### Production setup (Vercel + GitHub OAuth)

1. Create a GitHub OAuth App: [Developer settings → OAuth Apps](https://github.com/settings/developers)
   - **Homepage URL**: your production site URL (e.g. `https://your-project.vercel.app`)
   - **Authorization callback URL**: `https://your-project.vercel.app/api/callback`
2. In the Vercel project → Settings → Environment Variables, add:
   - `GITHUB_CLIENT_ID` — OAuth App Client ID
   - `GITHUB_CLIENT_SECRET` — OAuth App Client Secret
   - `CMS_BASE_URL` — same production origin as above (e.g. `https://your-project.vercel.app`)
3. Redeploy. Open `/admin/` → **Login with GitHub**.
4. Invite editors as **collaborators** (write) on [matyldajandova/daisyazylweb](https://github.com/matyldajandova/daisyazylweb).

OAuth API routes live in `api/auth.js` and `api/callback.js` (Vercel serverless only). Build injects `base_url` into the served `config.yml` via `scripts/prepare-cms-config.js`.

#### Collections

- Config source: `admin/config.yml` (served as `/config.yml` and `/admin/config.yml`)
- `animals` → `cms/animals.json`
- `partners` → `cms/partners.json`

### Hosting notes

- **Vercel**: `vercel.json` builds with `npm run build` and publishes `_site/`. Serverless `/api/*` handles Decap GitHub OAuth.
- Make sure the host serves:
  - `/sitemap.xml` and `/robots.txt`
  - `/llms.txt`
  - `/admin/`, `/api/auth`, `/api/callback`, and `/images/uploads/`
